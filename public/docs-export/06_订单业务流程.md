# 06 订单业务流程

## 订单类型

| 类型 | 入单方式 | 取衣方式 | 还衣方式 | 说明 |
|------|----------|----------|----------|------|
| A | 到店 | 到店自取 | 自取 | 最常见，无配送 |
| B | 到店 | 到店交件 | 配送到家 | 客户送来，我们送回 |
| C | 预约 | 骑手上门取 | 配送到家 | 全程无需到店 |

## 来源渠道

`store`（门店）/ `miniapp`（小程序）/ `meituan`（美团）/ `douyin`（抖音）/ `third_party`（第三方）

---

## 完整状态流转图

### A 型订单（到店自取）

```
到店 → received
     → sent_wash → factory_in → factory_sorted → washing
                → initial_check → ironing → final_check → packing
                → factory_out → store_in → on_shelf
                → completed（客户取件）
```

### B 型订单（配送送回）

```
到店 → received
     → [与A型相同洗涤流程]
     → on_shelf → delivering → completed
```

### C 型订单（上门取+配送）

```
下单 → ordered → assigned → picking_up → pickup_done → received
     → [与A型相同洗涤流程]
     → on_shelf → delivering → completed
```

### 异常流程

```
任意状态 → cancelled（退单）
任意状态 → compensated（退赔）
```

## derivedStatus 逻辑

`ClothesStock.tsx` 中的 `derivedStatus(order)` 函数：

根据订单中**所有衣物**的状态，计算订单整体显示状态（用于左侧列表的状态徽章）。规则：

1. 若任意衣物为 `compensated` → 订单显示 `compensated`
2. 若任意衣物为 `cancelled` → 订单显示 `cancelled`
3. 取所有衣物状态中**阶段数最小**的状态作为订单状态
   - 即订单以最落后的那件衣物的状态为准

## 收单流程（ReceiveOrder）

```
1. 搜索/创建会员
2. 选择订单类型（A/B/C）+ 来源渠道
3. 录入衣物（可多件）
   ├── 选品类目录（Step1 of AddGarmentModal）
   ├── 选颜色（Step2）
   └── 选瑕疵（Step3）
4. 为每件衣物选择挂点（可选）
5. 确认总金额、输入备注
6. 结账
   ├── 余额支付
   ├── 现金支付
   ├── 扫码支付
   └── 混合支付
7. 打印收衣标签 + 小票
```

## 标签编码规则

格式：`S01{orderNo}{garmentNo3}{attachNo2}`

示例：
- 订单 `1012569`，第1件衣物，主件：`S011012569001 00`
- 订单 `1012569`，第1件衣物，第1个附件：`S011012569001 01`

```
S01        → 门店前缀（Store 01）
1012569    → 订单号
001        → 衣物序号（3位补零）
00         → 附件序号（00=主件，01=第一附件，依次类推）
```
