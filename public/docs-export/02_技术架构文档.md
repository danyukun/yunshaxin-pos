## 1. 系统总览

### 1.1 业务背景

本系统为多门店干洗品牌的一体化运营平台，核心使用场景分两端：

| 端 | 使用者 | 核心诉求 |
|---|---|---|
| **POS 门店端**（Web） | 门店收银员 / 店长 | 快速开单、挂衣管理、收款打印、营销核销 |
| **用户端**（微信小程序） | C 端客户 | 线上下单、进度查询、优惠领取、配送预约 |
| **管理后台**（Web） | 品牌运营 / 总部 | 多店数据报表、价格统一管控、员工权限 |

## 2. 分层架构设计

客户端层包含 POS 门店端 Web (React + Tailwind) 和用户端微信小程序 (Taro/UniApp)。

API 网关层负责统一鉴权（JWT/微信Session）、路由分发、限流熔断、日志追踪、SSL卸载。

核心服务层包含：
- Order Service :3001 - 订单全生命周期
- Customer Service :3002 - 会员体系
- Catalog Service :3003 - 商品价格
- Store Service :3004 - 门店员工权限

内部服务层（仅内网）：
- Notify Service :4001
- Print Service :4002
- Payment Service :4003
- Report Service :4004

数据层：PostgreSQL (Supabase) + Redis + Object Storage (OSS/S3)

## 3. 服务进程拆解

### 3.1 核心服务

#### Order Service :3001
职责：订单全生命周期管理（创建/编辑/挂点/批次/配送/结单）
依赖：Customer、Catalog、Payment、Print、Notify

#### Customer Service :3002
职责：会员体系与营销权益管理（CRUD/等级/余额/优惠券/地址）

#### Catalog Service :3003
职责：衣物目录、定价、服务项、洗护周期管理

#### Store Service :3004
职责：门店基础信息与员工权限（RBAC）

### 3.2 内部服务

- Notify Service: 多渠道消息推送（微信Push/短信）
- Print Service: 统一管理门店打印机（小票/水洗唛/批次清单）
- Payment Service: 支付渠道封装（微信/支付宝/会员卡/美团/抖音）
- Report Service: 数据汇总分析（营业日报/月报/会员分析/挂点报告）

## 4. 完整调用链

### POS 开单收款
```
POS Web → API Gateway (验JWT) → Order Service
  ├─ Customer Service (会员信息+优惠券)
  ├─ Catalog Service (价格+周期)
  ├─ Payment Service (收款)
  ├─ Print Service (小票+水洗唛)
  └─ Notify Service (推送客户)
```

### 小程序在线下单
```
微信小程序 → API Gateway (验openid) → Order Service
  ├─ Catalog Service (价格预览)
  ├─ Customer Service (会员权益)
  ├─ Payment Service (JSAPI支付)
  ├─ Notify Service (通知门店+客户)
  └─ 返回订单成功
```
